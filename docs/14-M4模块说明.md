## 1. 这个模块是干什么的

一句话：**M4 是整条诊断链路的展示与交互闭环。它负责把前面的诊断结果落库读取并展示，同时通过调用 LLM 实现“STAR 重写”和“单轮问答”，并将前端三栏 UI 与后端接口完全打通。**

> 输入（report_id + 可选经历ID + 问答记录）  ──►  输出（报告详情 / STAR重写结果 / 问答点评）

M4 是整个项目对用户最终呈现的窗口，包含三个核心 API 和一个 Streamlit 前端页面。

## 2. 代码在哪

| 文件 | 干什么 |
|---|---|
| `backend/app/routers/report_router.py` | 接口入口：`GET /api/report/{id}`、`POST /api/rewrite`、`POST /api/qa` |
| `backend/app/services/report_service.py` | 负责根据 ID 从数据库获取完整报告 |
| `backend/app/services/rewrite_service.py` | 负责调用 LLM 进行 STAR 法则重写及评分提升预测 |
| `backend/app/services/qa_service.py` | 负责单轮问答的点评逻辑与落库 |
| `backend/app/contracts/report_schema.py` | 数据表格（Pydantic 模型）：路由的请求和响应格式 |
| `backend/tests/test_m4.py` | 4 个核心单元测试（包含成功获取与 404 异常覆盖） |
| `frontend/streamlit_app.py` | 前端三栏 UI 布局（输入、诊断、重写）及与后端 API 的交互 |

## 3. 怎么单独使用

### 3.1 配置
项目根目录放好 `.env`（数据库配置 `DATABASE_URL` 及 LLM 相关 Key）。

### 3.2 启动后端
> cd backend
> python -m uvicorn app.main:app --reload

### 3.3 启动前端
在项目根目录新开一个终端：
> streamlit run frontend/streamlit_app.py

浏览器会自动打开 `http://localhost:8501`，即可看到三栏界面。

### 3.4 测试接口
1. 在浏览器打开 `http://127.0.0.1:8000/docs`。
2. 找到 `GET /api/report/{id}`，填入已有的 `report_id` 测试。
3. 找到 `POST /api/rewrite` 测试 STAR 重写。
4. 找到 `POST /api/qa` 测试单轮问答点评。

## 4. 接口说明

### 4.1 GET /api/report/{report_id}
**请求**：路径参数 `report_id`（整数）
**响应（200）**：返回 `ReportDetailResponse` 结构，包含匹配分、差距、风险、问答记录、重写记录等。
- **404**：找不到该报告。

### 4.2 POST /api/rewrite
**请求**：
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `report_id` | int | 是 | 要重写的报告 ID |
| `experience_id` | string | 否 | 指定要重写的经历（默认 `proj_1`） |

**响应（200）**：返回 `RewriteResponse`，包含 `before`, `after`, `star` 四要素，以及 `improved_score`（重写后的预估分数）。
- **404**：找不到报告。

### 4.3 POST /api/qa
**请求**：
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `report_id` | int | 是 | 所属报告 ID |
| `question` | string | 是 | 面试官的问题 |
| `answer` | string | 是 | 用户的回答 |

**响应（200）**：返回 `QAResponse`，包含 `comment`（AI 的点评审意见）。

## 5. 数据契约

严格遵循 `backend/app/contracts/report_schema.py` 中的定义：

- `ReportDetailResponse`：包含 `id`, `resume_id`, `jd_id`, `score`, `gaps`, `risks`, `qa`, `rewrite`。
- `RewriteRequest` / `RewriteResponse`：包含 `report_id`, `experience_id`；响应包含 `before`, `after`, `star`, `improved_score`。
- `QARequest` / `QAResponse`：包含 `report_id`, `question`, `answer`；响应包含 `comment`。

## 6. 内部是怎么工作的

### 获取报告
> 前端请求 GET /api/report/{id}
> → 路由调用 report_service.get_report_by_id
> → 查数据库反序列化 json 字段
> → 返回 ReportDetailResponse

### STAR 重写
> 前端请求 POST /api/rewrite (包含 report_id)
> → 路由调用 rewrite_service.generate_star_rewrite
> → 提取原经历与风险点，拼接 Prompt 发送给 LLM
> → 接收 LLM 的 JSON 结果并更新数据库 rewrite 字段
> → 返回重写对比与 STAR 拆解

### 单轮问答
> 前端请求 POST /api/qa
> → 路由调用 qa_service.evaluate_answer
> → 调用 LLM 对用户回答进行量化指标评估
> → 将 QA 记录追加到数据库 qa 字段
> → 返回点评结果 comment

## 7. 怎么跑测试

| 层 | 命令（项目根目录或 backend 目录） | 说明 |
|---|---|---|
| 单元 + 接口测试 | `pytest backend/tests/test_m4.py -v` | 使用 `unittest.mock` 隔离了数据库和 LLM，秒回 |
| 全量测试 | `pytest backend/tests` | 运行所有人的所有测试（M1-M4） |

**测试分布**：M4 包含 4 个自动化测试用例（正常获取、404 异常、重写成功、问答成功），当前全部通过（4 passed）。

## 8. FAQ

- **问：前端点击“开始诊断”报 `LLM_UPSTREAM_ERROR` 怎么办？**
  答：这是由于 M1 或 M2 调用底层 LLM 时 Key 或 URL 配置不对导致的，不属于 M4 的报错。请检查根目录 `.env` 文件中 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 是否配置正确，并确保后端已重启。

- **问：前端界面全白，或者出现红色报错？**
  答：请检查 `frontend/streamlit_app.py` 是否依赖第三方网络资源，或者后端 `uvicorn` 服务是否正常启动。如遇 404，属于数据库没有生成初始数据，请先跑通 M1+M2 的 `/api/analyze` 生成报告 ID。

- **问：单元测试时一直找不到文件或模块？**
  答：请在项目根目录下运行 pytest，或者确保你的终端路径与测试文件路径匹配。使用 `pytest backend/tests/test_m4.py -v` 能够精准定位。
