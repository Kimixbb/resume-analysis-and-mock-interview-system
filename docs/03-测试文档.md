## 1. 测试计划

### 1.1 测试目标
验证「基于多Agent协作的简历诊断与模拟面试系统」全链路闭环（解析→匹配→拷问→重写）的可用性、稳定性和接口契约的准确性，确保 W11 终期答辩演示流程无阻断，达成质量门要求。

### 1.2 测试范围
- **包含**：M1解析、M2匹配、M3风险与五问、M4 STAR重写、前端UI三栏渲染、SQLite三表落库、API接口逻辑、LLM降级与异常兜底。
- **不包含**（依据设计文档 8.3）：用户登录/多版本、OCR/PDF解析、多轮追问、语音TTS/ASR、一键排版导出Word、雷达图等明确不做的功能。

### 1.3 测试策略与环境
- **测试环境**：Python 3.13, FastAPI TestClient, pytest, SQLite (测试库独立), Streamlit AppTest。
- **执行方式**：
  - **单元测试 (pytest)**：主要针对 `parser.py`、`match.py`、`interrogate.py`、`rewrite.py` 的核心逻辑及 Pydantic 校验。
  - **接口冒烟测试**：使用 Swagger UI (`/docs`) 或 Postman 验证 7 个 API 的连通性。
  - **集成测试**：`parse → match/interrogate → report → rewrite/qa` 全链路串行流转。
  - **E2E演示演练**：使用 Streamlit 界面跑通「坏简历+高要求JD」的标准演示脚本。

### 1.4 质量门与准出标准
- **CI门槛**：pytest 全绿（覆盖率不低于 80%）+ 接口冒烟测试 100% 通过。
- **接口冻结**：Agent间 JSON 契约严格按设计文档第5节，校验失败触发 1 次重试，仍失败则走降级兜底，不允许导致服务崩溃 (500)。
- **验收标准**：完全满足设计文档中 8.1（核心验收路径）和 8.2（功能验收清单A1-A10）。
