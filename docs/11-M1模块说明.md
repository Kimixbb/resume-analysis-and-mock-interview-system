## 1. 这个模块是干什么的

一句话：**M1 是整条诊断链路的第一步，把用户粘贴的简历文本和 JD 文本，变成后面所有模块都能用的结构化 JSON。**

```text
输入（两段纯文本）                输出（两个结构化对象）
resume_text（简历原文）   ──►   parsed（ResumeParsed：技能/经历/教育/量化数据）
jd_text（岗位JD原文）     ──►   req    （JDReq：硬技能/职责/关键词/最低年限）
```

## 2. 代码在哪

| 文件 | 干什么 |
|---|---|
| `backend/app/routers/parse.py` | 接口入口：`POST /api/parse`。只转发 |
| `backend/app/services/parse_service.py` | 干活：校验、拼 Prompt、调 LLM、补字段 |
| `backend/app/contracts/parse.py` | 数据表格（Pydantic 模型）：进出接口、跨模块传数据 |
| `backend/app/prompts/parse.md` | 给 LLM 的提示词 |
| `backend/tests/test_parse_*.py` | 单元测试 + 接口测试 + 真实 LLM 集成测试 |
| `backend/fixtures/parsed.json` | 本模块的真实输出样例（契约对照基准） |

## 3. 怎么单独使用

### 3.1 配置
项目根目录放好 .env（OPENAI_API_KEY 等填真实值，模板见 .env.example）

### 3.2 启动后端
```bash
cd backend
python -m uvicorn app.main:app --reload
```

### 3.3.1 浏览器
打开 http://127.0.0.1:8000/docs 找到 POST /api/parse，填入 resume_text 和 jd_text，点击 Execute 执行

### 3.3.2 脚本
backend/scripts/try_parse.py，在项目根目录运行
```python
import httpx
from pathlib import Path

d = Path(__file__).resolve().parents[1] / "fixtures"
r = httpx.post(
    "http://127.0.0.1:8000/api/parse",
    json={
        "resume_text": (d / "resume_bad.txt").read_text(encoding="utf-8"),
        "jd_text": (d / "jd_backend.txt").read_text(encoding="utf-8"),
    },
)
print(r.status_code, r.json())
```

## 4. 接口说明（POST /api/parse）

### 4.1 请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `resume_text` | string | 是 | 简历纯文本，strip 后 100–8000 字，**超出自动截断到 8000** |
| `jd_text` | string | 是 | JD 纯文本，strip 后 50–8000 字，**超出自动截断到 8000** |

### 4.2 响应（200）

| 字段 | 类型 | 说明 |
|---|---|---|
| `parsed` | ResumeParsed | 结构化简历 |
| `req` | JDReq | 结构化岗位要求 |

响应示例（真实返回，有删减）：

### 4.3 错误（统一格式 `{"code": ..., "message": ...}`）

| HTTP | code | 什么时候出现 | message 长这样 |
|---|---|---|---|
| 400 | `INVALID_INPUT` | 文本为空/过短；请求体不是合法 JSON；缺字段 | `简历字数不足100字` / `请求体不是合法 JSON：…` / `请求参数不合法：Field required` |
| 422 | `LLM_OUTPUT_INVALID` | LLM 输出不是 JSON / 不符合契约（含重试一次后仍失败） | `模型输出不符合约定` |
| 500 | `LLM_UPSTREAM_ERROR` | LLM 超时（30s）/ 网络异常 | `模型服务请求失败` |

## 5. 数据契约

字段与 `fixtures/parsed.json` 完全一致。

**ResumeParsed**

| 字段 | 类型 | 说明 |
|---|---|---|
| `raw_text` | string | 简历原文。**LLM 不返回它，后端用请求原文填**，可直接当标红定位的基准 |
| `skills` | string[] | 技能清单 |
| `experiences` | Experience[] | 经历列表（可能为空） |
| `education` | Education[] | 教育经历 |
| `metrics` | string[] | 整份简历的量化数据（可能为空） |

**Experience**（每段经历）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一编号。LLM 忘填/重复时**后端自动补 `exp_1`、`exp_2`…**，下游可放心当主键用 |
| `kind` | string | project / work / intern（模型给别的词也不会报错，当 other 处理即可） |
| `title` / `org` | string | 项目名或职位名 / 公司或组织 |
| `start` / `end` | string | 时间，尽量 `YYYY-MM`，可能为空 |
| `raw` | string | **该段经历的原文摘录（原样、不改写）**，M3 靠它定位标红 |
| `bullets` | string[] | 做过的事，一条一句 |
| `metrics` | string[] | 这段经历里的量化数据 |

**Education**：`school` / `major` / `start` / `end` / `degree`，均可为空。

**JDReq**

| 字段 | 类型 | 说明 |
|---|---|---|
| `hard_skills` | string[] | JD 要求的硬技能 |
| `responsibilities` | string[] | 岗位职责，一条一句 |
| `keywords` | string[] | 关键词（QPS、缓存……） |
| `min_years` | int | 最低年限，JD 没写就是 0 |

## 6. 内部是怎么工作的

```text
校验并规整两段文本（空/过短→400；超长→截断）
   ↓
拼 Prompt（prompts/parse.md 当 system + 两段文本当 user）
   ↓
调 LLM（core/llm.py：超时 30s、失败重试 1 次、JSON 提取、按 ParseResult 验收）
   ↓
后端收尾：覆盖 raw_text 为请求原文 + 给经历补唯一 id
   ↓
返回 ParseResponse
```

## 8. FAQ

- **Swagger 粘贴报 400 `JSON decode error`**：字符串里带了真实换行。JSON 里换行必须写成 `\n`；或者用第 3 节的脚本调，不用操心转义。
- **集成测试显示 skipped**：`.env` 还是占位符。填好真实 Key 和模型名后自动生效。
- **返回 422**：先看是不是模型名/服务地址配错导致输出格式崩了；`llm.py` 内部已自动重试一次，仍失败才 422，前端按「生成失败，请重试」提示即可。
