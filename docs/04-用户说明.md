## 1. 系统说明

把你的**简历**和想投岗位的**招聘要求JD**粘贴进来，系统自动给你出一份**简历报告**，告诉你：

1. **匹配度**：这份简历和这个岗位打多少分（0–100），差在哪 3 点；
2. **风险标红**：简历里哪些句子是面试官一眼就能戳穿的"雷区"；
3. **模拟面试**：针对雷区逐条"拷问"你，并点评你的回答；
4. **STAR 重写**：把写得最差的一段经历帮你改好，给出改前/改后对比和预估分数。

## 2. 开始之前准备

| 准备 | 说明 |
|------|------|
| 电脑装好 Python 3.13 | 去 python.org 下载安装；安装时勾选"Add Python to PATH"。如果之前没建过虚拟环境，直接跳过这步的例外说明 |
| 一个大模型 API Key | 一串以 `sk-` 开头的"钥匙"，OpenAI / DeepSeek 等都行，后台有余额即可。诊断全靠 AI 生成，**必须联网且配置了可用的 Key**，否则用不了 |
| 本项目的代码 | 下载或克隆仓库的 main 分支 |

## 3. 第一步：装环境

打开终端，进入项目文件夹，执行两条命令：

```bash
cp .env.example .env
pip install -r requirements.txt
```

然后编辑刚生成的 `.env` 文件，填上你的 Key：

```ini
OPENAI_API_KEY=sk-你的Key粘贴到这里
```

- 用 **OpenAI 官方**：其余两行保持默认，不用动。
- 用 **DeepSeek**（或其他兼容 OpenAI 接口的服务）：照 `.env` 里的注释把 `OPENAI_BASE_URL` 和 `OPENAI_MODEL` 两行改成对应服务的地址和模型名（示例已写在 `.env.example` 注释中）。

## 4. 第二步：启动系统（每次使用都要，要开 2 个终端窗口）

**终端 1 —— 启动后端**（先停在项目根目录）：

```bash
cd backend
python -m uvicorn app.main:app --reload
```

看到 `Uvicorn running on http://127.0.0.1:8000` 就算成功。

**终端 2 —— 启动前端**（重新开一个终端，回到项目根目录，不要在 backend 里）：

```bash
streamlit run frontend/streamlit_app.py
```

浏览器会自动打开 `http://localhost:8501`，看到「简历诊断与模拟面试系统」页面就绪。

## 5. 第三步：怎么用（页面上就 4 个动作）

### ① 左栏：粘贴简历和 JD

- 「**简历纯文本**」：打开你的简历文件，全选复制文字粘贴进来。要求 100–8000 字（太短会提示，超长自动截取前 8000 字）。不支持上传 PDF/Word，请复制里面的文字。
- 「**目标岗位 JD**」：把招聘页的职责和要求完整复制进来。要求 50–8000 字。

### ② 点「开始诊断」

点左栏的「🚀 开始诊断」按钮，页面会显示三步进度（解析 → 匹配/拷问 → 保存），通常几十秒到一分钟出结果。完成后自动分三栏展示：

- **中间栏「匹配分与风险拷问」**：综合匹配分 + 「三条关键差距」+ 简历原文标红。
- **右边栏「致命追问」「STAR 重写」**：见下面 ③④。

看懂风险标红：被红底圈出来的句子都是"面试官会戳穿"的写法，共三类：

| 类型 | 什么样算 |
|------|----------|
| 空话 | 只写形容词，如"认真负责、沟通能力强、学习能力强" |
| 无数字 | 说"大幅提升/显著优化"，但整句没有任何数字、百分比 |
| 逻辑矛盾 | 时间对不上，如时间段起止颠倒、在校时间和工作时间重叠 |

### ③ 右栏：致命追问（模拟面试）

- 系统最多出 5 题，**一题一题来**：答完点「提交点评」，看到 AI 点评后再答下一题（不能跳题、不能回头修改已提交的答案）。
- 每题在输入框里写回答（1–1000 字），建议写具体事实：什么背景、你做了什么、结果如何，别只喊口号。
- AI 每次给一句可执行的改进建议；全部答完会汇总展示所有问答。
- 没查出致命问题时，这里会显示「未发现致命问题 ✅」，跳过本步即可。

### ④ 右栏：STAR 重写

- 点「🪄 生成 STAR 重写」，系统自动挑出简历里**最薄弱的一段经历**（「改前」可看原文），按 STAR 法则（情境-任务-行动-结果）重写出参考版本。
- 「改后」文本框里的内容可以直接复制去改简历；旁边会给出重写后的预估分数和原分对比。
- 想重写时再点一次即可重新生成。

### 报告的保存与找回

- 每次诊断都会保存报告，浏览器地址栏会带上 `?report_id=数字`，**刷新页面或重开浏览器都能找回这份报告**。
- 未点「开始诊断」前的输入内容，刷新后会丢失。
- 点「🧹 清空当前报告」可回到输入状态，开始下一轮；历史报告仍保留在本地数据库里。

## 6. FAQ

| 页面提示 | 原因 | 怎么办 |
|----------|------|--------|
| 无法连接后端 | 终端 1 没启动、被关掉了或者还在报错 | 重新执行第 4 节终端 1 的命令，确认出现 `Uvicorn running on ...` 再操作 |
| 服务超时 / 保存失败，请重试 | AI 服务慢或网络不稳 | 直接重试一遍，一般就好 |
| 生成失败，请重试 | AI 返回的内容不合规范 | 直接重试一遍 |
| 简历太短 / JD 太短 | 粘贴内容没达到最低字数（100 / 50 字） | 把完整内容贴进去，别只贴标题或摘要 |
| 回答不能为空 | 追问的输入框没填 | 写几个字再提交 |

其他常见问题：

- **一次诊断要等多久？** 系统要调用 AI 服务 4–5 次，所以是几十秒到一分钟量级，卡住超过一分半可以重试。
- **历史数据存哪、能删吗？** 所有报告存在 `backend/data/app.db` 一个文件里。想全部清空，先关掉终端 1，再删掉这个文件即可（数据库文件在系统里创建，不用手动建）。
- **前端连不上 8000 端口？** 8000 被其他软件占用时，可以换个端口启动后端（如 `--port 8001`），并把 `frontend/streamlit_app.py` 开头的 `API_BASE` 里的 `8000` 改成同样的端口号。

## 7. 如何关闭程序

两个终端窗口里各按一次 Ctrl+C（或直接关掉窗口）即可，先关前端/后端都行。已保存的报告在下次启动后仍能通过原来的网址找回。
