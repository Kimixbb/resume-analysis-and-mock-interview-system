## 1. 模块职责

M3 接收 M1 输出的 `parsed`（结构化简历）和 `req`（结构化岗位要求），先由确定性规则找出简历中的风险片段，再由 LLM 针对风险生成追问，并选出最值得重写的一段经历。

M3 与 M2 都依赖 M1，但彼此独立，由前端在 M1 完成后并行调用。M3 不写数据库，结果由前端汇总后再调用 M4 的 `/api/report` 落库。

输入输出一句话：

```text
parsed + req
  → risks（标红片段 + 原因）
  → questions（1–5 条，带 risk_index）
  → weakest_experience_id（最差经历）
```

## 3. 接口：POST /api/interrogate

请求体直接复用 M1 的 `POST /api/parse` 响应：

```json
{
  "parsed": {
    "raw_text": "简历原文",
    "skills": ["Python"],
    "experiences": [],
    "education": [],
    "metrics": []
  },
  "req": {
    "hard_skills": ["Python"],
    "responsibilities": ["开发接口"],
    "keywords": [],
    "min_years": 0
  }
}
```

`parsed.raw_text` 必须非空，否则返回 400。

响应体：

```json
{
  "risks": [
    {
      "type": "逻辑矛盾",
      "text": "2024.09-2024.06",
      "reason": "起止时间倒置",
      "experience_id": "proj_1",
      "start": 101,
      "end": 116
    }
  ],
  "questions": [
    {
      "text": "这个项目的时间为什么是倒置的？",
      "risk_index": 0
    }
  ],
  "weakest_experience_id": "proj_1"
}
```

字段说明：

| 字段 | 类型 | 规则 |
|------|------|------|
| `risks` | RiskItem[] | 按原文位置排序；没有风险时为空数组 |
| `risks[].type` | string | `空话` / `无数字` / `逻辑矛盾` |
| `risks[].text` | string | 原文片段，必须能在 `raw_text` 中定位 |
| `risks[].reason` | string | 简短原因 |
| `risks[].experience_id` | string \| null | 风险所属经历；无法判断时为 null |
| `risks[].start` / `end` | int | 相对 `raw_text` 的字符区间，`end > start` |
| `questions` | Question[] | 0–5 条；没有风险时为空 |
| `questions[].text` | string | 追问内容 |
| `questions[].risk_index` | int | 指向 `risks` 数组下标 |
| `weakest_experience_id` | string \| null | 最值得重写的经历 id |

错误格式统一为 `{"code": "...", "message": "..."}`：

| HTTP | code | 条件 |
|------|------|------|
| 400 | `INVALID_INPUT` | 缺 `parsed` / `req`，或 `parsed.raw_text` 为空 |
| 422 | `LLM_OUTPUT_INVALID` | 模型输出非法、追问数量越界、过滤后没有有效追问 |
| 500 | `LLM_UPSTREAM_ERROR` | 模型服务超时、网络错误或 HTTP 异常 |

## 4. 规则层与 LLM 的分工

### 4.1 规则层：找风险、定位置

`interrogate_rules.py` 不调用 LLM，负责三类确定性检测：

| 类型 | 判定方式 |
|------|----------|
| 空话 | 命中“认真负责、沟通能力强、一致好评”等评价性词表 |
| 无数字 | 命中“大幅、显著、明显”等模糊词，且同一句没有数字、百分比、QPS、毫秒等指标 |
| 逻辑矛盾 | 识别 `2024.09-2024.06` 这类起止时间，开始时间晚于结束时间 |

每条规则结果都带：

- `text`：原文片段；
- `start` / `end`：在 `raw_text` 中的字符区间；
- `experience_id`：判断片段落在哪段经历里，找不到则为 `null`。

`interrogate_locate.py` 再用 `locate_span()` 校验一次：优先相信规则给的偏移，不一致时全文查找；仍找不到就跳过该风险，避免返回越界区间。

### 4.2 LLM：出追问、选最差经历

规则层已经确定“哪里有风险”，LLM 不再重新找风险，只负责：

- 针对 `risks` 生成 1–5 条追问；
- 每条追问绑定一个 `risk_index`；
- 选出 `weakest_experience_id`。

Prompt 在 `prompts/interrogate.md`，要求问题具体、引用风险原文、按致命程度排序、不编造风险。

服务层会做二次校验：

- `risk_index` 越界或重复的追问直接丢弃；
- 过滤后一条不剩则抛 `LLMOutputInvalid`；
- LLM 给的 `weakest_experience_id` 不在 `parsed.experiences` 里时，回退到规则评分选择。

## 5. 内部流程

```text
parsed + req
  → scan_rules() 找候选风险
  → locate_span() 校验偏移
  → 转成 RiskItem
  → 没有风险：直接返回空 questions
  → 有风险：拼 prompt + parsed + req + risks
  → model_json(..., schema=InterrogateResult)
  → 过滤越界/重复 risk_index
  → 校验 weakest_experience_id，失败则规则兜底
  → InterrogateResponse
```

`core/llm.py` 负责超时、JSON 提取、格式错误重试一次和异常转换；M3 服务不再重复重试。

## 6. 标红渲染

`interrogate_highlight.py` 提供：

```python
render_highlighted(raw_text: str, risks: list[RiskItem]) -> str
```

输出示例：

```html
<span title="#1 逻辑矛盾：起止时间倒置"
      style="background:#ffe0e0;border-bottom:2px solid #e05252">
  2024.09-2024.06<sup>1</sup>
</span>
```

特点：

- 原文和 `title` 都做 HTML 转义，避免简历内容注入；
- 支持多个风险区间重叠；
- 换行转成 `<br>`；
- 该 HTML 不放进 `/api/interrogate` 响应，前端用返回的 `risks` 调这个函数即可。

## 7. 单独使用

在项目根目录配置 `.env`，安装依赖后启动后端：

```bash
cd backend
python -m uvicorn app.main:app --reload
```

打开 `http://127.0.0.1:8000/docs`，找到 `POST /api/interrogate`，把 `backend/fixtures/parsed.json` 的内容作为请求体执行。

也可以用命令行：

```bash
curl -X POST http://127.0.0.1:8000/api/interrogate \
  -H "Content-Type: application/json" \
  -d @backend/fixtures/parsed.json
```
